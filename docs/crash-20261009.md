## Failed check identified from full disassembly

The incoming branch is at VidSchSubmitCommand+0x501 (address
fffff806`8d5219e1), inside the +0x4ed block. It loads source ID from
[rsi+0x74] into R8 and plane index into R9. The source/plane mapping
([r14+R8*8+0xD68], per-plane stride 0x130, mapping field +0xBC) selects

that entry's dword at +0x70 against 2. Equality jumps to the explicit
0x119/0x100000 bugcheck. Source=1 and plane=1 match the dump parameters.

meaning of state 2 is not established by disassembly alone. Do not label it

## Further offline investigation

CDB now works against the copied dump with Microsoft symbols. No MEMORY.DMP
was found. The source1/plane1 mapping and independent-flip table entries are
absent from this triage dump; the adapter table pointer itself is available.

Important correction: the stride-0xA0 table at adapter+0xDE8 is the independent
flip state table, not the VIDSCH_FLIP_QUEUE object. This is established by
VidSchEnterIndependentFlip, VidSchExitIndependentFlipInternal and
VidSchiSubmitIndependentFlip accessing the identical table/stride/field.

- VidSchEnterIndependentFlip+0x240 writes state+0x70 = 1.
- VidSchiSubmitIndependentFlip+0x1b1 checks that field against 1;
  +0x21a writes 2, then increments pending counts (+0x74 etc.).
- VidSchExitIndependentFlipInternal handles states 1/2 and changes the field
  to 0 or 3 depending on the exit path.
- VidSchSubmitCommand rejects regular MPO submission when that same mapped
  independent-flip state is 2. This is the exact crash condition.

Thus state 2 is associated with an independent flip having been submitted,
not the separate suspend/resume flag. The private enum label is unavailable.
The dump supports conflicting presentation state at regular MPO submission;
it does not establish why the independent-flip exit/handoff failed.

## Adopted activation mitigation

Eligibility hooks now deny DirectFlip/MPO as soon as filterEnabled is set,
independent of whether a previous frame was corrected. The Windows 24H2
Present filter path waits at least 500 ms after all hooks are enabled before
accessing/applying the correction. Reactivation resets the delay. Original
Present continues during the grace period; no presentation-thread sleep.
This is a timed handoff mitigation, not proof that all independent flips have
completed their exit. The resident bridge ABI is unchanged.
Offline checks: timing boundary/reset unit test passes; generated hook.cpp
compiles. No live activation performed.
